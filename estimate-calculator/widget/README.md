# Estimate Calculator — Standalone Widget

An embeddable JavaScript widget version of the Estimate Calculator plugin. Works on **any HTML page** — no WordPress required — while keeping all the customization power of the full plugin.

Same calculation logic, same multi-step flow, same GHL integration. Just drop it into a `<div>` anywhere.

---

## Files

| File | Purpose |
|---|---|
| `estimate-calculator.js` | The widget itself — a single self-contained JS file with inline CSS |
| `proxy.php` | Standalone PHP backend that talks to GHL API V2 (keeps your API key off the browser) |
| `embed-example.html` | Full working example showing every config option |
| `README.md` | This file |

---

## Quick Start

### 1. Upload the files

Upload `estimate-calculator.js` and `proxy.php` to your server.

```
https://yourdomain.com/estimate/estimate-calculator.js
https://yourdomain.com/estimate/proxy.php
```

### 2. Configure the proxy

Open `proxy.php` and fill in the top `CONFIG` section:

```php
$GHL_API_KEY      = 'YOUR_PRIVATE_INTEGRATION_ACCESS_TOKEN';
$GHL_LOCATION_ID  = 'YOUR_LOCATION_ID';
$GHL_PIPELINE_ID  = 'YOUR_PIPELINE_ID';
$GHL_STAGE_ID     = 'YOUR_STAGE_ID';

$ALLOWED_ORIGINS = [
    'https://yourdomain.com',
    'https://www.yourdomain.com',
];
```

### 3. Embed on any HTML page

```html
<div id="estimate-calc"></div>

<script src="https://yourdomain.com/estimate/estimate-calculator.js"></script>
<script>
  EstimateCalculator.init({
    container: '#estimate-calc',
    endpoint:  'https://yourdomain.com/estimate/proxy.php',
    calendar:  'https://link.yourdomain.com/widget/booking/XXX',
    pixel:     { type: 'facebook', id: '1234567890' }
  });
</script>
```

That's it — the calculator loads with sensible defaults. See `embed-example.html` for the full config reference.

## Configuration Reference

Every option is optional. Defaults are used for anything you don't set.

### Core

| Option | Type | Description |
|---|---|---|
| `container` | String / Element | CSS selector or DOM element where the widget renders. Default `#estimate-calc` |
| `endpoint` | String | URL to POST submissions. Usually your `proxy.php`. Leave empty for client-side-only demos |
| `nonce` | String | (WP only) nonce generated by `wp_create_nonce('ec_submit')` |
| `action` | String | (WP only) WordPress AJAX action name. Default `ec_submit` |
| `services` | Array | Which services to enable. Any combination of `interior`, `exterior`, `cabinet` |
| `calendar` | String | Your GHL calendar widget URL. Shown after submission |

### Business Info (Google Online Estimate Schema)

The widget automatically outputs **Schema.org JSON-LD structured data** compliant with Google's Online Estimate spec. This helps the calculator surface in Google Search with rich results.

```js
business: {
  enabled:    true,  // set false to disable schema output
  type:       'HousePainter',  // HomeAndConstructionBusiness, HousePainter, Plumber, RoofingContractor, etc.
  name:       'All American Trade Work',
  phone:      '+1 541-697-3141',
  email:      'info@yourdomain.com',
  url:        'https://yourdomain.com',
  logo:       'https://yourdomain.com/logo.png',
  street:     '123 Main St',
  city:       'Portland',
  region:     'OR',        // State / region abbreviation
  postal:     '97201',
  country:    'US',        // ISO 3166-1 alpha-2
  areaServed: 'Portland, OR metro area',
  currency:   'USD'        // ISO 4217
}
```

**What gets output:**

1. **On page load** — a `Service` schema with:
   - `provider` → `LocalBusiness` / `HousePainter` / etc.
   - `potentialAction` → `QuoteAction` (the Google Online Estimate action)
   - `hasOfferCatalog` → one `Offer` per enabled service

2. **When results display** — an `Offer` schema with:
   - `priceSpecification` → `minPrice` and `maxPrice` (the estimate range)
   - `seller` → your business
   - `itemOffered` → the specific service

Test your schema at the [Google Rich Results Test](https://search.google.com/test/rich-results).

### Square Footage Ranges

Each client can set their own sq ft breakpoints. Set `xlargeOpen: true` to render the largest tier with a `+` suffix (e.g., "401-600+").

```js
sqft: {
  interior: {
    small:      [0, 150],
    medium:     [151, 250],
    large:      [251, 400],
    xlarge:     [401, 600],
    xlargeOpen: true
  },
  exterior: {
    small:      [0, 1500],
    medium:     [1501, 2500],
    large:      [2501, 4000],
    xlarge:     [4001, 6000],
    xlargeOpen: true
  }
}
```

Exterior `Small` is rendered as "Up to 1,500 sq ft", and Extra Large as "4,001+ sq ft".

## Backend Options

You have **four** choices for the `endpoint`:

### Option 1: WordPress REST API (recommended for external/non-PHP sites)

See **Option 3** below — moved into its own section because it's the cleanest path for embedding on a different domain than your WP install. The remaining options below are for sites that share infrastructure with the plugin or don't need WordPress at all.

### Option 1b: Standalone PHP Proxy (works without WordPress)

Use the included `proxy.php`. Works on any PHP 7.4+ host. Configured with your GHL credentials once — clients never see the API key.

```js
endpoint: 'https://yourdomain.com/estimate/proxy.php'
```

### Option 2: WordPress Plugin AJAX (same-site only)

If the widget is on **the same WordPress site** as the plugin:

```js
endpoint: 'https://wp-site.com/wp-admin/admin-ajax.php',
nonce:    'NONCE_FROM_wp_create_nonce',
action:   'ec_submit'
```

WordPress nonces are tied to a session, so they don't work cross-origin. For external sites use Option 3 below.

### Option 3: WordPress REST API (best for external non-PHP sites)

**Recommended** when the widget lives on a different site (Webflow, Framer, plain HTML, static-host, etc.) than your WordPress install.

The widget pulls its config (pricing, services, labels, custom services, colors, etc.) directly from the WP plugin's REST API and posts submissions there too — so admin changes in WP propagate instantly to every external embed.

**Setup in WP:**
1. Activate the plugin and go to **Estimate Calc → External Sites**
2. Check **"Enable REST endpoints"**
3. Click **"+ Add Site Token"**
4. Fill in:
   - **Label** (e.g., "Client A site")
   - **Allowed Origins** (one per line — `https://client-site.com`, `https://www.client-site.com`)
5. Save and copy the generated token

**Embed on the external site:**
```html
<div id="estimate-calc"></div>

<script src="https://wp-site.com/wp-content/plugins/estimate-calculator/widget/estimate-calculator.js"></script>
<script>
EstimateCalculator.init({
    container:   '#estimate-calc',

    // WordPress REST mode
    wpRestUrl:   'https://wp-site.com/wp-json/ec/v1',
    siteToken:   'paste_the_token_from_wp_admin',
    fetchConfig: true,    // pull pricing/services/labels from WP at init

    // Optional per-site overrides — these win over what WP returns
    colors: { primary: '#your_brand_color' }
});
</script>
```

**How it works:**
- `fetchConfig: true` → widget GETs `${wpRestUrl}/config` with `X-EC-Site-Token` header and merges the response into its config
- `endpoint` defaults to `${wpRestUrl}/submit` automatically; submissions POST there with the same token header
- The WP plugin validates the token + origin, runs the calc, pushes to GHL — exactly the same flow as the WordPress shortcode

**Security:**
- The GHL API token never leaves your WP server
- Each site token has its own origin allow-list, so a stolen token can only be used from approved domains
- Revoke a token instantly in WP admin → the external site stops working immediately
- Multiple tokens supported — one per client site, all driven by the same WP install

### Option 4: Client-Side Only (demo mode)

Omit `endpoint` entirely. The widget will calculate and display results but won't save leads. Useful for demos or when integrating with a custom backend via the `onSubmit` callback.

```js
EstimateCalculator.init({
  container: '#demo',
  onSubmit: function(data, estimate) {
    // Handle submission in your own way
    fetch('/your-own-api', { method: 'POST', body: JSON.stringify({ data, estimate }) });
  }
});
```

## GHL Private Integration Setup

This widget uses **GHL Private Integration API V2.0** — the secure way to connect without agency admin access.

1. Log into the client's **GHL sub-account**
2. Settings → Integrations → **Private Integrations** → Create
3. Enable these scopes:
   - `contacts.write`
   - `contacts.readonly`
   - `opportunities.write`
   - `locations.readonly`
   - `calendars.readonly` (if using calendar)
4. Copy the **Access Token** → paste into `proxy.php` as `$GHL_API_KEY`
5. Copy the **Location ID** → paste as `$GHL_LOCATION_ID`
6. Copy your **Pipeline ID** and **Stage ID** from the URL when viewing your pipeline → paste into `proxy.php`

## What Happens on Submission

```
User clicks Get Estimate
    ↓
[Client-Side] Calculate estimate from config pricing
    ↓
[Client-Side] POST to endpoint with all data
    ↓
[proxy.php] Upsert contact in GHL (name, email, phone, tags, custom fields)
    ↓
[proxy.php] Create Opportunity in configured pipeline (if set)
    ↓
[Client-Side] Fire tracking pixel conversion event
    ↓
[Client-Side] Show inline results + calendar embed
    ↓
User books estimate appointment → GHL handles booking
```

You can run multiple calculators on the same page:

## Security Notes

- **Never put your GHL API key in the widget config** — always use `proxy.php` or a similar server-side endpoint
- Restrict `$ALLOWED_ORIGINS` in `proxy.php` to only the domains that should be able to submit
- Always serve over HTTPS
- Consider rate-limiting `proxy.php` at the server level (nginx, Cloudflare) to prevent abuse

## Accessing the Calculation Engine Directly

If you want to use the math without the UI:

```js
var estimate = EstimateCalculator.calculate('interior', {
  small_rooms: 2,
  medium_rooms: 1,
  doors: 3,
  condition: 'good'
}, {
  smallRoom: 270,
  mediumRoom: 2000,
  // ... full pricing object
});

console.log(estimate); // { total: 3250, low: 160, high: 13 }
```
